# paseo

官网文档：https://paseo.sh/docs · https://paseo.sh/docs/schedules
社区介绍：https://linux.do/t/topic/2401586

## 是什么

Paseo 在你自己机器上运行 coding agent，是**编排层**而不是 agent 本身：它启动并监管你已安装、已登录的 CLI（Claude Code、Codex、OpenCode、Cursor、Gemini 等），你的订阅、配置、skills、MCP 全部原样保留，Paseo 只是在上面加 UI（桌面 / 移动 / Web / CLI）、relay 和编排能力。

核心特点：

- 支持多个 Coding Agent 统一管理；
- 支持 Claude Code、Codex、Copilot、OpenCode、Pi 等工具；
- 支持桌面端、移动端、Web 端和 CLI；
- 支持通过二维码连接手机或其他客户端；
- 支持远程连接本机或服务器上的 Paseo daemon；
- 支持通过 relay / WebSocket 实现远程访问能力；
- 适合多模型切换、多 Agent 并行任务、远程查看和移动端掌控。

核心组件是本机 **daemon**，配置与状态在 `~/.paseo`（`PASEO_HOME`），可选端到端加密 relay 供手机配对（也可以走 Tailscale / TCP 直连）。

## 安装

三种方式：桌面应用（推荐，自带 daemon 自动启动）、Linux 包（.deb/.rpm/AppImage）、Docker（`ghcr.io/getpaseo/paseo`）。命令行是**独立的 npm 包，桌面应用不会自带 `paseo` 命令**：

```shell
npm install -g @getpaseo/cli
paseo          # 启动 daemon，问是否开 relay 并打印配对二维码
```

CLI 与桌面应用共用 `~/.paseo`，装好即连上已在跑的 daemon，无需重新配对。

手机配对：Settings → your host → Pair Device，扫二维码。

## 核心概念

Project > workspace > 会话（agent、Terminal、Browser、Diff…）

1. **Project**：一个目录 / git 仓库 / GitHub 项目是一个 Project，侧边栏顶层，一个 Project 可有多个 workspace。
2. **Workspace**：Paseo 的组织结构围绕工作区展开，而不是围绕聊天（"organized around workspaces, not chats"）。工作区是任务发生的容器：有一个工作目录，可同时运行多个会话，每个会话在应用里是一个 tab。
   - a. 项目包含工作区，每个工作区都是一个独立的工作空间
   - b. 工作区包含会话：会话可通过 tab 页切换；一个 workspace 里可同时有多个 agent、终端、浏览器、diff
   - c. 每个工作区都有一个隔离模式：**本地模式**用现有目录（如主 checkout）；**Worktree** 创建/打开托管 git worktree，任务需要自己的目录和分支时用
3. **Session / Agent**：跑在 workspace 里的具体会话。建 workspace 和建 agent 是两个独立动作；`paseo run` 可指定 `--workspace <id>` 放进已有 workspace。
4. **Provider**：Paseo 与某个外部 agent CLI 之间的契约（如何启动、流式输出、回传输入、支持哪些模式）。原生适配 Claude Code / Codex / OpenCode / pi，其余走 ACP 目录（Cursor、Gemini、Copilot 等 25+）。
5. **Orchestration**：agent 可以协调其他 agent —— 按 provider/模型派生子 agent、并行分工、按 ID 互发消息、建 workspace/worktree、跨机器（`--host`）、创建 schedule 与 heartbeat。开启方式：Settings → your host → Agents → Enable Paseo tools（默认关闭）。
6. **Hub**：与"定时"相对的触发方式，由外部事件（评论、@提及）启动 agent。

最佳实践：**不要混用原生终端和 Paseo 来管理同一个会话。**

## CLI 日常使用

```shell
paseo run "fix the tests"            # 启动 agent（默认等完成，--background 立即返回）
paseo ls                             # 列出 agent
paseo attach <id>                    # 流式看输出
paseo send <id> "also fix linting"   # 追加任务
paseo logs <id>                      # 看时间线
paseo stop <id>                      # 停止
```

常用变体：

```shell
paseo run --provider codex "refactor the API layer"
paseo run --new-workspace worktree --worktree-mode branch-off --new-branch feature/x --base origin/main "implement feature X"
paseo run --workspace <workspace-id> "review the current diff"
paseo run --output-schema schema.json "extract release notes"   # 只返回符合 schema 的 JSON
```

- 从人用的 shell 里裸 `paseo run` 会在当前目录新建一个 local workspace；已是 Paseo agent 时（通过 `PASEO_AGENT_ID` 识别）会变成调用者的 subagent，同 workspace。
- 远程 daemon 用全局 `paseo --host devbox:6767 ...`（或 `PASEO_HOST`）。
- 其他命令组：`paseo project create/ls`、`paseo workspace create/ls/rename/archive`、`paseo terminal ...`、`paseo script start/stop`、`paseo permit ls`、`paseo provider diagnostic claude`。

## Schedules 与 Heartbeats

文档：https://paseo.sh/docs/schedules

两者共用同一个 cron 引擎，但语义完全不同：

| | Schedule | Heartbeat |
| --- | --- | --- |
| 目标 | **每次启动一个全新 agent** | 发回**同一个已有 agent**，继续同一段对话 |
| 管理面 | 检视 / 暂停 / 恢复 / 单次运行 / 更新 / 删除 | 刻意轻量：MCP 只能建/删；CLI 额外只能改 cron 周期（改 prompt = 删了重建） |
| 典型用途 | 每日 triage、周报、维护清理 | 让当前 agent 定期自查、持续推进 |

都不是外部事件触发——那种场景用 Hub。

典型场景：

- 新鲜的周期性任务：每日 triage、报告、维护扫荡（刷依赖、审文档、清 stale 分支）
- Heartbeat：让长任务 agent 自己每隔 N 分钟醒来接着干
- 构建看护：每 5 分钟查 CI / EAS / Docker / release build，直到通过，失败就修

### 创建方式（4 种）

1. **应用里**：Schedules 视图，填 agent 设置 + cron + 仓库 + prompt（官方称这是主要方式）
2. **聊天里**：自然语言让 agent 通过 Paseo MCP 建
3. **CLI**：`paseo schedule create`（headless / 脚本）
4. **MCP**：agent 程序化创建/管理

聊天示例 prompt：

> "Every weekday at 9am, triage new GitHub issues and PRs and summarize what needs attention."
> "Check the release build every 5 minutes until it passes, and fix the cause if it fails."
> "Keep working on this refactor — wake yourself every 20 minutes and continue where you left off."

管理同样可以下指令："pause the triage schedule"、"make the build check run every 2 minutes instead"、"run it once now"、"delete it"。

### CLI：创建 Schedule

```shell
# 夜间重构（Codex，每 30 分钟，最多 16 次，10 小时后过期）
paseo schedule create \
  --every 30m --name overnight-refactor \
  --provider codex/gpt-5.5 --cwd ~/dev/my-app \
  --max-runs 16 --expires-in 10h \
  "Continue the refactor. Run the focused checks. Leave a short status note."

# 构建看护（Claude，每 5 分钟）
paseo schedule create --every 5m --name build-watch \
  --provider claude/opus-4.7 --cwd ~/dev/my-app --max-runs 24 \
  "Check the release build. If it failed, inspect logs, fix the cause, and rerun."

# 工作日 UTC 14:00 的 GitHub triage，创建后立刻跑一次
paseo schedule create --cron "0 14 * * 1-5" --timezone UTC --run-now \
  --name github-triage --provider opencode/openrouter/glm-5.1 --cwd ~/dev/my-app \
  "Triage GitHub issues, PRs, and failing checks. Summarize what needs attention."

# 纽约时间早上 9 点（自动处理夏令时）
paseo schedule create --cron "0 9 * * 1-5" --timezone America/New_York \
  --name morning-triage --provider codex/gpt-5.5 --cwd ~/dev/my-app \
  "Review overnight CI failures and summarize anything urgent."
```

### CLI：Heartbeat

只能在运行中的 Paseo agent 会话内创建（依赖 `PASEO_AGENT_ID`）：

```shell
paseo heartbeat create --cron "*/20 * * * *" --name heartbeat \
  "Check the current task state and continue with the next useful step."
paseo heartbeat update <id> --cron "*/10 * * * *"   # 只能改 cron/时区
paseo heartbeat delete <id>
```

### 管理

```shell
paseo schedule ls
paseo schedule inspect <id>
paseo schedule logs <id>
paseo schedule pause <id> / resume <id>
paseo schedule run-once <id>          # 立即手动跑一次
paseo schedule update <id> --every 10m --max-runs 6
paseo schedule delete <id>
```

### 节奏（Cadence）要点

- **cron 是权威表示**：`--every 5m` / `1h` 只是预设，会被编译成 cron 存储，**不是**从创建时刻起算的滚动间隔。
- 时区默认 **UTC**；`--timezone <IANA>` 让 cron 按本地挂钟解释，`nextRunAt` 仍存 UTC 瞬间，跨夏令时本地时间不变。
- 默认**等下一个匹配的 cron 时刻**才首跑；要立即跑一次加 `--run-now`。
- 远程 daemon：`paseo --host <target> schedule create ...`，且显式传 `--cwd`（本地目录在远程机器上不一定存在）。
- Heartbeat **必须用原始 `--cron`** 表达式，`--every` 预设只对新 agent schedule 有效。
