# 独立数学老师 AI 题库：需求与分阶段开发计划

更新日期：2026-10-12  
文档状态：需求草案，可用于原型验证与开发拆分。标注“建议”“待确认”的内容尚非最终决策。

## 1. 产品目标与范围

帮助独立数学老师将已有教学资料整理成可追溯、可校对的题库，按年级、知识点、难度和教学题组挑题，输出可编辑的 Word 与可打印的 PDF，并支持 Markdown 和离线 HTML。

核心流程：上传资料 → 拆题与对照校对 → 选择入库 → 分类检索 → 组织母题与变式 → 组卷草稿 → 排版预览 → 导出。

设计原则：

- AI 辅助识别、分类和推荐，老师确认后形成正式内容。
- 保留原始资料与识别结果，能追溯每道题的来源。
- 一道题只保存一份，通过关系归属多个知识点和教学题组。
- 先解决录题、找题、组卷、导出闭环，再扩展生成变式与学生学习分析。
- 本地优先为建议方案；本地运行不代表调用 AI 时资料不出本机。

首版不包含：学生在线考试、自动批改、支付、多教师协作、复杂学情分析、自动生成变式、PPT 导出。以上可按实际使用反馈另行立项。

## 2. 用户场景

1. 导入一份含答案的数学试卷，拆题后排除不需要的题目，校对公式与配图后入库。
2. 截图录入一道题，AI 建议知识点、年级与难度，老师修正并保存。
3. 按多个知识点筛选题目，将代表题与已有变式整理为教学题组。
4. 每个知识点选择指定数量的母题，为每道母题配指定数量的变式，生成可调整的讲义。
5. 从同一份组卷草稿导出教师版、学生版及课后作业版。
6. 查明题目的原始出处，修订答案，并保留之前已经使用的试卷版本。
7. 后续按学生或班级排除近期已经讲过、布置过的题目。

## 3. 题目录入

### 3.1 输入格式与支持边界

| 格式 | 需求 | 边界与处理方式 |
| --- | --- | --- |
| 截图 | 上传图片、粘贴截图；识别文字、公式与配图 | 首版优先清晰印刷题；手写、模糊、倾斜图片提示人工复核 |
| PDF | 支持文字型与扫描型 PDF | 分别处理文字提取与视觉识别；保留原页，处理跨页题、多栏题及集中答案 |
| Markdown | 解析题目、公式、图片、答案 | 首版约定题目分隔与答案标记；不符合约定时进入校对流程 |
| LaTeX | 解析题目、公式、答案及配图 | 首版约定支持的环境；外部图片需一并提供，自定义宏与缺失依赖明确提示 |

首版不承诺任意排版均可自动正确拆分。Word 导入可作为后续增强，不影响 Word 导出要求。

### 3.2 入库流程

上传 → 解析任务 → 拆题预览 → 原文与结果对照 → 修正 → 勾选题目 → 确认入库。

- 每题可选择录入或排除；支持全选、取消、批量确认与只查看异常题。
- 支持合并误拆题、拆分粘连题、调整题目边界与小问归属。
- 支持补图、裁图、调整题干/选项/解析中的配图位置。
- 展示题目数、待核对数、成功数和失败数，允许部分入库。
- 重复上传不直接重复入库；失败任务可重试，成功部分不重复处理。
- 识别期间的人工编辑不能被迟到的 AI 结果覆盖；重新识别应提供差异比较。

### 3.3 答案匹配

- 支持题后答案、文末集中答案与独立答案文件。
- 以文档、章节、原题号、小问等信息共同匹配，不能只依赖题号。
- 答案缺失、数量不一致、存在多种候选时进入待核对状态。
- 保留原始答案；教师修订及 AI 生成答案分别记录，不能覆盖原始答案来源。
- “答案页”区分原始资料答案页与导出生成的集中答案页。

### 3.4 来源追溯与任务记录

每题记录：原文件、文件摘要、页码或位置、原题号、原始截图/引用区域、导入批次、识别时间、处理状态。文字源文件记录可定位的章节或段落。

任务记录处理进度、失败原因、重试次数、模型及用量；能获取费用时展示实际费用，否则明确标为估算。支持取消未完成任务，避免无限重试。

## 4. 题目内容与数据关系

| 对象 | 核心内容 |
| --- | --- |
| 题目 | 唯一 ID、题型、题干、选项、配图、表格、适用年级、难度、预计用时、审核状态 |
| 小问 | 顺序、题干、分值、答案、共用材料或配图关系 |
| 解答 | 简明答案、详细解析、多种解法、评分步骤、方法总结、来源类型、审核状态 |
| 来源 | 原文件与定位信息；同一道题可关联多个来源 |
| 知识点 | 标准名称、层级、别名；与题目为多对多关系 |
| 教材定位 | 教材版本、年级、学期、章节；与知识点分开管理 |
| 标签 | 方法标签、用途标签等；支持人工及 AI 建议 |
| 教学题组 | 标题、代表题、变式题、顺序、变式类型、题组方法总结 |
| 组卷 | 选题规则、题目版本、顺序、分值、留白、模板与导出记录 |

初始题型建议支持单选、多选、填空、解答、证明、作图；选项数量不固定为四个。共用材料的题目需要保持组合关系。

题目状态建议为：草稿 → 待核对 → 已确认 → 已归档；删除进入回收站。“没有答案”“有答案未审核”“有已审核答案”应可区分筛选。

修改需有历史记录与恢复能力。已导出的试卷保存内容快照或固定版本引用，题库后续修改不能悄悄改变历史试卷。

## 5. 分类、标签与难度

### 5.1 目录与标签

- 界面可按年级、知识点显示目录，但目录只是查看方式，不复制题目。
- 教材章节、知识点、解题方法与用途标签独立管理。
- 知识点使用可维护词表，支持别名、合并、改名、批量调整与未分类列表。
- AI 优先从词表选择，可提出新增建议，由老师确认。
- 支持多知识点归属；可设置一个主要知识点，用于组卷配额归属。
- 老师确认的标签不能被自动重新分类覆盖。

### 5.2 难度

- 难度为 1—5 星，允许“未评定”，不将缺失值自动视为三星。
- 分别保留 AI 建议与教师确认值，并记录适用学段或学生层次。
- 用老师选定的样题建立星级参照，预计用时作为独立字段。
- 后续若引入学生答题数据，实际表现与教师难度并存，不直接互相覆盖。

## 6. 母题、变式与教学题组

建议用“教学题组”表达母题关系：母题是某个题组内的代表题，同一道题可以在不同题组承担不同角色。

- 创建、编辑、复制、归档题组；增删成员不删除原题。
- 为变式标注类型，例如改数值、改条件、改设问、方法迁移、综合应用。
- 保存讲解顺序、关联理由及题组方法总结。
- 默认每个题组一题作为代表题；多代表题属于后续可扩展项。
- 第一版支持人工关联已有题；后续提供相似题与变式候选推荐。
- AI 生成变式另行开发：新题先进入草稿，验证条件、答案、图形与难度后由老师确认。
- 相似题不等于重复题，也不必然是适合作为变式的题。

## 7. 检索与展示

- 按年级、教材、知识点、标签、题型、难度、是否有答案、答案审核状态、来源组合筛选。
- 多选知识点明确“满足任意一个”与“同时满足全部”；难度支持范围。
- 支持题干关键词搜索，展示原文与公式，提供答案显示开关。
- 支持按题目或题组浏览、批量操作、收藏及保存常用筛选条件。
- 返回结果说明命中的知识点或标签，避免筛选含义不透明。
- 公式相似搜索、语义搜索为后续增强；不能替代确定性的条件筛选。

## 8. 组卷与排版

### 8.1 选题规则

支持按年级、知识点、每个知识点的母题数量、每个母题的变式数量、难度等生成草稿；可进一步限定题型、总题量、分值与预计时长。

需明确并实现以下规则：

- 同一道题在同一份试卷默认只出现一次。
- 跨知识点题目按主要知识点或本次指定知识点计入题量配额；知识点覆盖可多计，题量不能重复计。
- 明确难度约束作用于单题还是整卷分布。
- 题量不足时显示缺口，允许换母题、减少数量或由老师主动放宽条件；不能静默放宽。
- 首版不自动生成题目补足缺口。
- 支持锁定题目、替换单题、拖动顺序、手动增删；替换后重新校验约束。
- 保存最终题目集合与规则；随机抽题可记录随机种子，方便复现。

### 8.2 排版与模板

支持教师版、学生版、课后作业版，并允许配置：

- 标题、班级/姓名栏、纸张尺寸、页边距、字体、页码。
- 大题分组、题号、分值、题目顺序、题目间距及答题留白。
- 题后答案或集中答案、是否包含解析、方法总结与教师备注。
- 题干与配图尽量同页；超长题可合理跨页，但不能截断公式或遮挡内容。
- 教师版默认包含答案解析；学生版和作业版默认不含答案、教师备注。

“题量不足”“未审核答案”“缺图”“公式渲染失败”等问题应在导出前集中展示。

## 9. 导出要求

| 格式 | 目标与验收重点 | 优先级 |
| --- | --- | --- |
| Word（.docx） | 正文与常见公式可编辑；明确 Word/WPS 兼容范围；保留图片、题号、间距与答案布局 | 首版核心 |
| PDF | 可直接打印；字体正常；公式完整；配图清晰；留白及分页符合预览 | 首版核心 |
| Markdown | 约定数学语法；图片与正文一并打包；换路径后仍能使用 | 完整基础版 |
| 离线 HTML | 断网可浏览、渲染公式和显示图片；依赖随包交付 | 完整基础版 |

- 同一份组卷内容供各导出器使用，但不承诺不同格式像素级一致。
- 复杂公式无法转换时必须提示，是否转为图片由明确策略决定，不能假装仍可编辑。
- 学生版须从输出数据中排除答案，不能只通过样式隐藏；图片与正文也要检查是否夹带答案。
- 记录导出时间、模板版本、题目版本、格式及失败原因。
- PPT 不在当前范围；未来如需要，应独立设计一题一页、长题拆页与分步揭示答案。

## 10. 数据可靠性、部署与成本

### 10.1 去重与恢复

- 完全重复导入提示；相似题提供比较后人工决定，不自动合并。
- 合并题目保留多来源、题组引用与使用记录。
- 题目删除可恢复；被试卷或题组引用的题目不应造成历史内容失效。
- 完整备份包含题目、图片、原文件、题组、模板与使用记录。
- 首版提供手动备份与恢复验证；后续自动定期备份。
- 支持开放格式的整库导出，避免只能依赖某个软件读取数据。

### 10.2 部署建议

建议先采用单老师、本机使用模式，正式技术选型在项目试用后决定。跨设备同步、云端部署、多用户权限后续另行设计。

基础录入、检索、编辑及已配置好的导出应不依赖 AI 服务在线；AI 不可用时保留手动处理入口。

外部 AI 调用需说明发送的资料范围，密钥不写入普通日志或默认分享包。导入资料如含学生姓名等信息，应提供裁除或脱敏方式。资料来源与使用范围作为元数据记录。

### 10.3 实现约束

- 对上传文件设定大小、页数和类型限制，并给出可理解的提示。
- 导入的 LaTeX、HTML 与外部资源按不可信内容处理，限制执行命令及任意文件访问。
- AI 任务有超时、取消、重试上限和用量记录；局部失败不丢失已完成内容。
- 明确支持的操作系统、安装方式、字体与排版依赖，升级前备份，数据迁移失败可恢复。

## 11. 后续教学使用记录

轻量记录学生或班级、使用日期、题目/题组、用途（讲解、练习、作业、测验）。组卷可排除指定时间范围内已经使用的题目。

后续再考虑错题、掌握情况、弱点推荐和重复练习策略，不将完整学生管理作为题库首版前提。

## 12. 公开项目调研与选型

调研日期：2026-10-12。以下基于公开仓库说明，尚未安装实测；未确认的功能不能视为支持，未提到的能力也不能直接视为不存在。

| 项目 | 已公开说明的能力 | 主要差距或待验证项 | 采用建议 |
| --- | --- | --- | --- |
| [MathBank](https://github.com/JudgePeach/math-question-bank) | 本地题库、截图 OCR、多格式拆题、AI 分类、组卷、PDF 与可编辑公式 Word 导出 | Markdown 解析尚不完善；教材小节为单值；多知识点关系、母题题组、按组抽题及全部目标格式需验证 | 第一试用候选 |
| [MathCyclus](https://github.com/JinLingxi/MathCyclus---Lingxi-Question-Bank-Assistant) | 截图转 LaTeX、自动标签与难度、题干答案分离、条件抽题、LaTeX/PDF | 围绕 LaTeX 文件组织，其他输入与 Word/HTML 导出需验证 | 已有大量 LaTeX 时重点试用 |
| [math_question_bank](https://github.com/qqppddbai/math_question_bank) | 本地题库、检索、手动组卷、Word/HTML/Markdown、学生错题、备份 | 批量录入为 JSON；PDF 与截图需外部预处理；PDF 通过浏览器打印 | 参考轻量流程与导出实现 |
| [Sitimo](https://github.com/barryhu705-beep/Sitimo) | LaTeX 导入、配套解析匹配、标签难度、拖拽组卷、PDF/LaTeX | 多来源 AI 录入与其他导出格式未确认 | 规范 LaTeX 资料场景候选 |
| [MathExamHub](https://github.com/vanabel/MathExamHub) | AI 关键词、相似题、题型管理、LaTeX 导入导出 | 对输入格式有约定，多来源录题存在差距 | 参考检索与相似题设计 |
| [tutor-exam-bank](https://github.com/Tom-Yang-Ben/tutor-exam-bank) | PDF 拆题、学生使用历史、变式生成、人工复核、Word 输出 | 仓库声明仅供浏览评估、不授权使用 | 仅作产品设计参考，不作为开发底座 |

许可核查：MathBank 标注 AGPL-3.0；MathCyclus 与 Sitimo 的 README 声明 MIT；qqppddbai/math_question_bank 本轮未找到明确许可。正式采用前核对具体版本的许可证及依赖许可；公开可读不等于可任意复用。

MathBank 的 AI 功能依赖外部 API，PDF 排版涉及本地 LaTeX 环境。“本地题库”不能解读为全部功能离线。

当前建议：先试用 MathBank；如果导入与导出质量满足真实资料要求，优先补齐题组和组卷规则。若核心内容结构无法支持多知识点、题组及版本保存，再比较改造成本与重新实现成本。

## 13. 分阶段开发计划

以下为建议安排。工期按一名有相关经验的全栈开发者、可获得老师持续反馈估算，不是承诺；试用结果、资料复杂度及二次开发底座会影响工期。每阶段先验收，再进入依赖它的阶段。

### 阶段 0：真实资料验证与选型（3—5 个工作日）

工作：

- 收集 30—50 道有代表性的真实题目及标准答案，覆盖四类输入、跨页、多栏、复杂公式、几何图、小问、集中答案及重复题号。
- 试跑 MathBank；按资料特点追加一个候选，记录实际支持与失败情况。
- 统计每题校对耗时、答案错配、配图遗漏、导出手修次数及 AI 用量。
- 确认学段、教材、设备、常用排版、可编辑公式要求和资料规模。
- 核对许可证，形成“采用现有项目/二次开发/重新实现”的决策。

交付：样题验收集、对比记录、功能缺口表、技术选型与更新后的工作量估算。

退出标准：全部样题有处理结果或明确失败原因；关键困难得到复现；确定底座与首版支持边界。不能仅凭 README 选择底座。

### 阶段 1：可靠的题库基础（1—2 周）

工作：

- 建立题目、小问、答案、来源、图片、知识点、标签与版本关系。
- 完成手动新增、编辑、公式预览、条件筛选和答案显示开关。
- 实现多知识点归属、审核状态、回收站、手动完整备份与恢复。
- 完成首个可安装或可启动的本地版本。

交付：无需 AI 也可用的题库原型。

退出标准：代表性题目能完整保存与显示；多个目录引用同一题；题目编辑与删除可追溯；在空数据环境中恢复备份后内容和附件一致。

### 阶段 2：AI 录题与校对（2—3 周）

工作：

- 优先接入截图与 PDF，再接入约定格式的 Markdown/LaTeX。
- 实现拆题预览、勾选排除、边界修正、补图、小问及答案关联。
- AI 建议年级、知识点和难度；支持老师确认及批量调整。
- 实现去重提示、任务进度、局部失败重试、用量记录和编辑保护。

交付：四类输入到已确认题目的完整录入流程。

退出标准：验收集中的每题可自动处理或通过明确的人工入口完成；漏题、缺图、答案不确定不能静默通过；重复重试不产生重复题。记录未经校对的识别准确情况与校对耗时，不用“可人工修复”冒充自动准确率。

### 阶段 3：教学题组与组卷（1—2 周）

工作：

- 支持代表题、变式类型、题组顺序与方法总结。
- 实现知识点母题配额、变式数量、难度与去重约束。
- 实现草稿、锁题、替换、排序、数量不足提示与规则保存。
- 固定组卷中的题目版本。

交付：可按“知识点 → 母题 → 变式”生成并调整的组卷草稿。

退出标准：跨知识点不重复计题；题量不足有明确提示；不自动放宽约束；手动替换后能复核规则；重新打开草稿与原结果一致。

### 阶段 4：Word/PDF 与首版交付（2—3 周）

工作：

- 实现教师版、学生版、课后作业版模板。
- 支持顺序、题间距、答题留白、答案布局、纸张与页边距。
- 完成 Word 可编辑公式输出、PDF 打印输出和异常提示。
- 打通安装、升级、备份恢复及操作说明。
- 由老师用真实备课任务试用并修复阻断问题。

交付：可日常使用的首版 MVP。

退出标准：代表性试卷在约定的 Word/WPS 环境与 PDF 中通过视觉检查，无公式截断、缺图、遮挡和答案泄漏；历史试卷不随题库编辑改变；完成一次“导入—组卷—导出—备份恢复”全流程验收。

### 阶段 5：完整基础版与效率增强（1—2 周）

工作：

- 增加 Markdown 资源打包及真正离线的 HTML 导出。
- 增加学生/班级的轻量使用记录与近期用题排除。
- 增加常用筛选保存、批量整理与定期备份。
- 按实际题库规模优化检索和批量处理。

交付：覆盖当前四种目标导出格式的完整基础版。

退出标准：断网打开 HTML 仍有图片和公式；Markdown 包换路径可用；用题排除可解释；备份可恢复。性能指标按阶段 0 确定的数据量与设备实测。

### 阶段 6：按反馈选择扩展（单独估算）

候选：相似题/变式推荐、语义搜索、AI 生成并验证变式、Word 导入、错题及学情、跨设备同步、多老师协作、PPT 课堂演示。

每项单独定义验收标准。自动变式需验证可解性、答案、图形与知识点一致性，并保留人工审核；不能因为前期数据已结构化就默认可以可靠生成。

### 里程碑与依赖

| 里程碑 | 完成阶段 | 可获得的成果 |
| --- | --- | --- |
| 选型决策 | 0 | 是否值得二次开发、有证据的范围和估算 |
| 可维护题库 | 1 | 手动录题、检索、恢复 |
| 智能录题闭环 | 2 | 多来源资料经校对入库 |
| 教学组织闭环 | 3 | 母题变式与规则组卷 |
| 首版日常可用 | 4 | Word/PDF、三类模板、稳定数据 |
| 当前基础需求完整 | 5 | Markdown/离线 HTML 及使用效率增强 |

按上述假设，首版约 6—10 周加阶段 0，完整基础版约 7—12 周加阶段 0。若复用项目已经通过对应验收，可直接缩减阶段，不重复开发；若解析和公式导出不通过，应先调整支持范围或工期。

## 14. 验收与风险控制

验收以真实题目和实际打印结果为依据，至少覆盖：

| 场景 | 必须检查 |
| --- | --- |
| 跨页、多栏、重复题号 | 不漏题；边界可修正；答案不串题 |
| 复杂公式、几何图、表格 | 原文可追溯；无静默缺失；导出完整 |
| 多知识点、多题组 | 单题不复制；配额无重复计数 |
| 题量不足、缺答案、缺图 | 明确提示，不悄悄补全或放宽 |
| 任务中断、重试、人工同时编辑 | 不重复入库，不丢内容、不覆盖新编辑 |
| 教师版与学生版 | 内容一致且学生输出不含答案、教师备注 |
| 修订题目后打开历史试卷 | 旧试卷保持原内容 |
| 更换电脑或恢复备份 | 题目、图片、来源、题组与模板完整 |

阶段 0 建立人工处理耗时基线，再确定可接受的自动识别成功率、单题校对时间及导出耗时。不得在未测样题前承诺统一准确率。

## 15. 开发前待确认事项

以下不阻碍阶段 0，但会影响后续设计：

1. 主要学段与教材版本；是否需要跨初高中使用？  要跨学科使用
2. 日常电脑系统、Word/WPS 环境及是否需要多设备？MACOS/windows，不需要多设备
3. 现有资料的格式占比、题量、扫描质量和是否主要为手写内容？pdf 居多，质量比较高，没有手写内容
4. 母题与变式目前如何组织；是否接受首版人工建立题组？一个母题后跟三个变式题，要求关联性比较强
5. Word 公式可编辑是否为强制要求；有哪些常用复杂公式？非强制要求
6. 是否接受外部 AI API、可接受的成本与资料发送范围？接受外部 AI API
7. 优先复用现有项目还是计划独立产品化？
8. 首版是否接受先交付 Word/PDF，随后补齐 Markdown/离线 HTML？
